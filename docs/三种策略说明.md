# 三种比赛策略说明（贪婪 / 侵略 / 保守）

> 代码位置：`contestant_ws/src/rmtc_bot/rmtc_bot/strategies/`
> 共享记忆：`brain.py` 的 `WorldMap` + `EventMemory`
> 现场切换：`decision_config.json` 的 `decision_type`

---

## 1. 一眼看懂

| 策略 | 目标 | 会攻击吗 | 资源 | 任务 | 实测均分（十图 ×3 种子） | 上限 |
| --- | --- | --- | --- | --- | --- | --- |
| **贪婪型** `greedy` | 资源 + 任务 | **从不** | 核心，主动搜刮 | 顺路优先做 | 32.8 | 45（30 资源 + 15 任务） |
| **侵略型** `aggressive` | 击杀与压制 | 主动找架打 | 只捡 4 格内的 | 顺路做 | 35.0 | 60（15 对抗 + 30 资源 + 15 任务） |
| **保守型** `conservative` | 不被接近 + 搜资源 | **从不** | 边躲边搜 | 安全时才做 | 30.3 | 45 |
| 综合型 `balanced`（默认） | 冲最高分 | 顺手打 + 收官补刀 | 主要收入 | 前 120 Tick 后补 | **43.7** | 60（多局打满） |

> 三种"人格"策略的分数上限天然不同：不攻击就拿不到 15 分对抗分，
> 所以贪婪/保守的理论上限是 45；侵略型上限 60，但资源只捡嘴边的，实际通常 35~45。
> **要冲总分第一，用 `balanced`；要按性格打，用前三个。**

## 2. 为什么能共享记忆

```
                 ┌──────────────────────────────┐
                 │  Brain（唯一实例）            │
                 │  ├─ WorldMap   地形/资源/敌车 │  ← 每 Tick 用感知刷新
                 │  ├─ EventMemory 事件约束      │  ← LLM 解析后写入
                 │  ├─ LoopGuard  防循环         │  ← 三种策略共用
                 │  └─ Strategy   当前策略对象   │  ← 可热切换
                 └──────────────────────────────┘
```

- 策略只**读** `brain.world` / `brain.events`，自己不存地图；
- `Brain.set_strategy()` 只替换策略对象，**不清空**地图、资源、敌车、事件记忆；
- 切换后下一 Tick 立刻沿用已有记忆，不需要重新探索（日志会打印"保留记忆：已知资源 N 处"）；
- 只有换场次（`session_id` 变化）才会整体清空——这是规则要求。

## 3. 贪婪型 `greedy`

**一句话**：只干活，不打架；被贴脸才抱头防御，防完继续跑。

### 决策顺序

```
1. 死亡 → wait
2. 在敌方攻击线内且 HP ≤ 45 → 防御（最多连续 1 Tick，下一 Tick 必须尝试脱离）
3. HP ≤ 35 且敌人 ≤ 3 格 → 逃跑
4. 在攻击线内且 HP ≤ 70 → 边撤边找下一个资源
5. 候选目标打分：
      任务点   5 / (0.45d + 0.25)
      资源     0.25 × 价值 / (0.45d + 0.3) × 1.15 × 远离敌人加成
      天使点   0.09 × 缺失HP / (d + 2)     （HP < 60 才考虑）
      探索     1.55 × 0.25 × 密度 × 新发现格数 / (d + 3.6)
6. 取最高分目标移动；HP ≤ 60 时绕开敌方攻击线
7. 走不到 → 换下一个候选；全部走不到 → 巡逻
```

### 关键取舍

- **不还手**：被追时用"逃跑 + 绕线"保命，而不是站桩对射；
- **防御只防一 Tick**：连续防御会被磨死，第二次必须移动；
- **资源偏好远离敌人**：同样 10 价值的资源，优先选离敌车远的那一侧。

### 事件反应

| 事件 | 反应 |
| --- | --- |
| 爆炸 / 世界分裂 | 禁区自动绕行（代价场里不可通行） |
| 天使恩泽 | HP < 60 时作为高价值目标去踩 |
| 天下无双 | **不去**（不攻击，拿了增益也没用） |
| 洁身自好 | 被贴脸时更愿意防御（对手打你会自伤 20） |
| 潘潘的神 | 低血时减少移动，避免叠易伤 |

## 4. 侵略型 `aggressive`

**一句话**：主动找人打，资源只捡路过的。

### 决策顺序

```
1. 死亡 → wait
2. 能攻击（1–2 格直线、非保护、不亏）→ ATTACK
3. HP ≤ 40 → 脱离，并进入 6 Tick 重整期（不主动接敌）
4. 血量 ≤ 50 且附近有天使点 → 先去回血
5. 选目标：优先残血/可斩杀；以下情况不追：
      - 对抗分已满（D ≥ 500）
      - 自己残血（HP ≤ 38）且对方不是残血
      - 一打多（≥2 个敌人）且自己 HP < 55
      - 出生保护期（打不了）
6. 没有追击目标 → 堡垒（AoE）> 辣椒陷阱 > 4 格内资源 > 6 格内任务点
7. 都没看到 → 去最后已知敌人位置 / 地图中心 / 前沿巡逻
```

### 防"无脑送"

- 追同一支队 **15 Tick 没造成伤害** → 拉黑 25 Tick，转去别处；
- 路径代价 > 3×直线 + 6（隔着墙）→ 放弃该目标；
- 对抗分打满后停止主动追猎，改为捡资源和做任务（把剩余时间换成资源分）。

### 事件反应

| 事件 | 反应 |
| --- | --- |
| 天下无双 | **优先争夺**：5×5 攻击是刷伤害最快的方式 |
| 火爆辣椒 | 敌人正好在十字线上时，主动踩点触发火线（交点免疫） |
| 天使恩泽 | HP ≤ 50 去回血 |
| 洁身自好 | 不打防御目标（会自伤且 0 伤害），改打非防御目标 |
| 爆炸 / 世界分裂 | 绕行，不拿命换输出 |

## 5. 保守型 `conservative`

**一句话**：保持距离，边躲边搜；被堵住才防御。

### 决策顺序

```
1. 死亡 → wait
2. 易伤期且被贴脸 → 防御（移动会再次获得易伤）
3. 危险判定：敌人 ≤ 2 格，或 HP ≤ 45，或（敌人在警戒半径 5 内且 HP ≤ 55）
      → 找一个"离敌人最远、还能顺手捡资源"的落脚点（5 步内）
      → 跑不掉且在攻击线内 → 防御
4. HP < 85 且附近有天使点 → 去回血
5. 资源评分额外乘 (1 + 0.06 × 离敌人距离)
6. 任务点若离敌人 < 3 格 → 暂时不做
7. 探索只去"离敌人 ≥ 3 格"的前沿
```

### 特点

- 存活率最高（实测死亡数通常 1~4 次），但资源获取慢；
- 不适合作为冲分主力，适合"开局被集火、先保命"的场次。

## 6. 三种策略共用的事件响应

事件由 LLM 解析成"类型 + 起始/结束 Tick + 坐标"，策略只决定去不去、躲不躲。
**八种事件没有一种是靠正则或关键词识别的。**

| 事件 | 统一处理 |
| --- | --- |
| 爆炸 | 生效前 3 Tick 起，矩形加入代价场禁区；已在区内会自动往外走 |
| 世界分裂 | 十字线提前 1 Tick 变为不可通行 |
| 幻术 | 方向反转；用 `last_action.effective_direction` 与实际发送方向比对，自动纠正 |
| 天使恩泽 | 按各策略血量阈值决定是否去 |
| 天下无双 | 侵略型争夺；贪婪/保守不去 |
| 火爆辣椒 | 交点安全；侵略型会用来打线上敌人 |
| 洁身自好 | 攻击评估自动跳过防御目标；被贴脸时优先防御 |
| 潘潘的神 | 移动会叠易伤：保守型直接防御，其他策略减少不必要移动 |

## 7. 防"反复无效动作"的三层机制

这是本次重点加固的部分。实测把最长无效停滞从 **245 Tick 压到 ≤8 Tick**。

### 第一层：目标进度跟踪

同一个资源/任务点连续 5 Tick 距离没有下降 → 判定"走不到"，拉黑 22 Tick，换目标。
追同一支队 15 Tick 没造成伤害 → 拉黑 25 Tick。

### 第二层：移动失败换向

上一 Tick 想走却没走动（撞墙、被占位、两车抢同一格）→ 接下来 3 Tick 不再往那个方向顶。
两台车同时想进同一格时，只要一方换向，死锁立刻解开。

### 第三层：全局抖动兜底

- 最近 12 Tick 只在**两个格子**之间往返 → 强制改走最远的前沿（10 Tick）；
- 活着、周围没敌人、却连续 3 Tick 不动 → 强制挪窝（"主动驻留"如堡垒除外，不会被误伤）；
- 任何策略抛异常 → 本 Tick 退化为 `wait`，进程不退出。

## 8. 实测数据（十张实验图 × 3 个种子，共 30 局/策略，3 台视野受限陪练）

| 策略 | 平均分 | 最高 | 平均资源 | 平均任务 | 平均伤害 | 动作构成 |
| --- | --- | --- | --- | --- | --- | --- |
| 贪婪型 | 32.83 | 45.0 | 82 | 2.83 | 0 | 只有 move / defend，**0 次 attack** |
| 侵略型 | 34.97 | 50.4 | 38 | 2.17 | 1017 | move / attack，**0 次 defend** |
| 保守型 | 30.33 | 45.0 | 65 | 2.83 | 0 | move / 少量 defend，**0 次 attack** |
| 综合型 | **43.67** | **60.0** | 63 | 2.67 | 974 | move / attack / defend 都有 |

分图明细见 [`十图实验与规则微调报告.md`](十图实验与规则微调报告.md)。

结论：

- 贪婪/保守 **零攻击**、侵略型 **零防御**，行为约束由代码结构保证（前者从不调用攻击分支，
  后者从不调用防御分支），不是"概率上不太打"；
- 三种策略的无效停滞都 ≤ 8 Tick（最长的一次是贪婪型 8 Tick，均为被堵后换向的过渡）；
- 每场 `invalid_actions` 保持 0（阵亡只发 wait，保护期不发攻击）；
- 想拿最高分，仍然推荐 `balanced`（它同时吃资源、任务、对抗三份分）。

## 9. 现场怎么切换

**必须手动切换 —— 程序自动切换不符合规则。**

规则 §2.3 原文两处：

> 「比赛期间允许队内讨论、按规定重启已封存程序，以及**按下述流程**切换预先封装的决策类型；
> 禁止现场修改源代码、算法实现、Prompt、其他决策参数或人工发送具体动作。」

> 「每队每场最多申请**两次人工策略切换**。切换须在比赛暂停期间或加赛之前提出，
> **经裁判批准并登记后**进行，比赛恢复后生效。……不得修改程序逻辑或借此**实施逐 Tick 人工控制**。」

切换成立要同时满足：**人工提出 + 暂停期间 + 裁判批准登记 + 每场 ≤2 次**。
程序若自己按局势在 `balanced/greedy/…` 之间跳，等于自我批准，绕开了这套流程，
和「不得借此绕过决策类型切换流程」的意图直接冲突。

**但"自适应"≠"切换"**：在**同一个** `decision_type` 内部按血量/资源/剩余时间调整权重或阈值，
属于赛前封存的算法本身，完全允许——`balanced` 就是这么干的（打分里 HP、资源、时间都在起作用）。
区别只在于**有没有更换枚举**。

本程序的实现也符合这一点：`set_strategy()` 全项目只有一个调用点，在 `node._watch_decision()` 里，
由 `decision_config.json` 的 mtime 变化触发——**只有人改文件才会切**，代码里没有任何自动调用。
日志里出现 `策略切换 1/2 → xxx` 就说明有人改过文件，可作为操作留痕。

如果确实想要"自己会变"的策略，合法做法是：赛前新增并登记一个枚举（例如 `adaptive`），
把它做成**单一决策类型**、内部自适应、不做枚举切换，并在 README 中写清作用与读取方式。

三种性格是三种完全不同的决策目标（只采集 / 主动接敌 / 躲着搜），所以默认由你决定，
程序不替你猜。

切换有三种方式，效果一样（都是改 `decision_config.json`，下一 Tick 生效）：

```bash
# 方式 1：启动前用启动器指定（最省事，记作本场初始档位，不计入 2 次限制）
./start_bot.sh test-token --decision greedy

# 方式 2：比赛停顿时手改，程序 2 秒内自动热切换（保留地图/资源记忆）
echo '{"decision_type": "aggressive"}' > decision_config.json

# 方式 3：手动起程序时用环境变量指向别的配置文件
RMTC_DECISION_CONFIG=$PWD/dc_greedy.json ./run_contestant.sh A '图灵队'
```

**开局前定档位不算"切换"**；比赛中途改才算，且每场最多 2 次、需裁判批准。

### 配置文件

```json
{"decision_type": "greedy"}
```

可选值：`greedy` / `aggressive` / `conservative` / `balanced`。
程序每 2 秒检查一次文件修改时间，改了才切换，**不清空记忆**。

### 规则约束（必须遵守）

- 枚举必须**赛前登记**（见 README 的“现场切档”一节）；
- 每场最多切换 **2 次**，且必须在暂停期间或加赛前提出、经裁判批准；
- 文件里只能有 `decision_type`，不能夹带坐标、目标 ID、动作序列；
- 程序内也做了硬限制：同一场第 3 次修改会被忽略并打警告。

### 建议的切换时机

| 场景 | 建议 |
| --- | --- |
| 开局对手明显更强、自己被针对 | 切 `conservative` 保资源 |
| 对手偏弱、想稳拿资源分 | 切 `greedy` |
| 需要靠击杀压制某个队 | 切 `aggressive` |
| 正常冲分 | 保持 `balanced` |

## 10. 想自己加第四种策略？

1. 在 `strategies/` 新建文件，继承 `Strategy`，实现 `decide(brain)`；
2. 复用 `self.resources()` / `self.reach_target()` / `self.heal_target()` / `self.flee_cell()`；
3. 在 `strategies/__init__.py` 的 `build_strategy()` 里注册；
4. 把名字加进 `config.DECISION_TYPES`（这一步等于"赛前登记"，比赛现场不能加）；
5. 用 `tools/sim.py --decision 你的名字` 跑 12 局，确认没有长时间停滞。
