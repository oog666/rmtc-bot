RMTC · Beyond Control · Algorithm Map

这台机器人怎么想：一帧感知到一发动作

整套程序只做一件事：把每个 Tick 的感知，折算成“每个候选动作值多少分”，然后选最高的那个。 下面六张图，从架构、时序、打分、几何、节奏到事件，把这套判断逻辑拆开看。

第一阶段 40 / 40（练习图满分） 第二阶段 60 / 60（可达上限） 决策耗时 3–5 ms 动作合法率 100 %

1总体架构：两条互不阻塞的链路

左边是 10 Hz 的控制回路，纯计算、无网络；右边是 AI 理解回路，跑在独立线程里。 模型再慢，也不会拖住任何一个 Tick。

图 1 · 架构：控制回路（左）与 AI 理解回路（右）解耦，AI 的任何延迟都不会占用动作窗口

2一个 Tick 里发生了什么

从收到感知到发出动作，只有 9 步，全部是内存计算。真正决定“选哪个动作”的只有第 6 步。

解析感知 protocol.py容错

字段缺失、类型不符、场次为空 → 直接丢弃本帧；绝不让进程退出。

场次对齐

session_id 变了就清空地图、资源、目标锁和动作缓存；tick 过期丢弃，重复则复用缓存动作。

融合世界模型 world.py

视野 9×9 标为畅通；障碍、资源、敌车上账；已知资源在视野里消失 = 被对手采走。

吸收 AI 结果

把后台线程算完的事件 JSON 做结构校验，再编译成禁区 / 堡垒 / 天使点等约束。

构建代价场 Dijkstra0.2 ms

一次算出到全图每格的距离。未知格 +0.075、敌车格 +7、敌车攻击线 +0.2~0.95，爆炸区不可通行。

给所有候选目标打分

资源、高价资源、任务点、天使点、堡垒、追击、探索——全部折算成“分/步”，取最高。

幻术补偿

如果上一 Tick 请求向右、实际向左，说明中了幻术：本 Tick 自动反着发，下 Tick 再用回执自检。

合法性兜底

方向必须合法；阵亡只发 wait；出生保护期不发攻击；任何异常退化为 wait。

发布动作 + 缓存

回填当前 tick 与 session_id，同 Tick 重发时直接复用，不重复推进策略。

图 2 · 单 Tick 时序：整个回路 3–5 ms，占 100 ms 窗口的 3%–5%

资源为什么用 0.32×距离？
路过去捡是“单程代价”，不是往返。系数小于 1 表示愿意为路边资源绕一小段； 实测该系数从 1.0 降到 0.32，第一阶段平均分从 31.6 升到 38.5。
对抗分满了还打吗？
D ≥ 500 之后追击权重 ×0.12，把时间让给资源；只在收官（剩余 < 180 Tick 且 D 不够）时 ×1.45 主动找人。

4战斗判定：三种几何，三种算法

规则里所有伤害都发生在“格子关系”上。程序把攻击拆成三种几何模板，逐一枚举后按收益排序。

几何 A · 攻击前先枚举四个方向，每个方向只取最近的敌人
几何 B · 唯一的范围伤害，也是刷伤害最快的手段
几何 C · 十字线：站在交点最安全，站在线上最危险

5500 Tick 的节奏：先攒分，再打架

三项分值的性价比完全不同：一个任务 5 分、一个资源 2.5~5 分、20 点伤害只值 0.6 分。 所以整场被切成“抢资源 → 补任务 → 刷伤害”三段，而不是从头打到尾。

图 5 · 节奏由“边际分数”决定：资源封顶后自动降权，伤害封顶后自动收手

6随机事件：把“自然语言”变成“时空约束”

程序从不解析公告文本。它把原文交给 LLM，只接收“类型 + 生效区间 + 区域”三个字段， 校验后编译成禁区或目标点。模型挂了，这部分约束为空，其他照常。

图 6 · 事件从“一句话”变成“一个带到期时间的禁区/目标点”
