# 代码说明：这套程序在做什么、怎么用、为什么这样设计

> 配套文件：`README.md`（快速上手）、`docs/算法图解.html`（图示化算法逻辑）
> 代码根目录：`contestant_ws/src/rmtc_bot/rmtc_bot/`

---

## 1. 目标：把规则直接翻译成优化问题

规则给的分值是线性的，因此"拿最高分"可以拆成三个可计算的目标：

| 阶段 | 计分公式 | 程序对应的策略 |
| --- | --- | --- |
| 第一阶段 | `40 × R₁ / 200` | 100 Tick 内尽可能多采集 → **在线定向越野（Orienteering）** |
| 第二阶段·资源 | `30 × min(R₂/120, 1)` | 抢 120 价值资源 → 资源优先，高价资源加倍 |
| 第二阶段·对抗 | `15 × min(D/500, 1)` | 打满 500 有效伤害 → 顺手打 + 收官补刀 |
| 第二阶段·任务 | `5 × M`（3 项） | 2 普通 + 1 高价 + 到达坐标 → 开局顺路做完 |

三条约束决定了架构：

1. **动作窗口很短**（100 ms / 500 ms），LLM 一次调用要几秒 → AI 必须异步，绝不能进控制回路；
2. **视野只有 9×9**，地图与资源位置未知 → 必须边探索边规划，并维护一张增量地图；
3. **随机事件只能用 LLM 理解** → 事件文本只进模型，本地只接收"已校验的结构化结果"。

## 2. 总体架构

```
                 ┌──────────────────────────────┐
 /team_X/perception ──► protocol.py 解析（容错）
                 │            │
                 │            ▼
                 │      world.py 世界模型（占据栅格 / 资源 / 敌车 / 临时墙）
                 │            │
                 │            ├──► brain.py 代价场（Dijkstra）
                 │            │        │
                 │            │        ├──► collector.py  第一阶段
                 │            │        └──► strategies/   第二阶段（四种策略）
                 │            │                 │
                 │            │                 ├── combat.py 攻击评估
                 │            │                 └── events.py 事件约束
                 │            ▼
 /team_X/action ◄── protocol.py 编码（回填 tick/session_id）
                 │
                 │   llm.py（独立线程，单并发）
 event_text ─────┴──► 统一网关 /v1/chat/completions ──► JSON 校验 ──► events.py
```

设计原则：

- **决策回路里没有网络、没有磁盘、没有阻塞调用**；
- 所有外部输入都当作"可能出错"处理：解析失败就丢帧，策略异常就 `wait`；
- 任何优化都必须能解释成"分数/步"。

## 3. 模块逐个说明

### 3.1 `protocol.py` —— 只做协议，不做策略

| 函数 | 作用 |
| --- | --- |
| `parse_perception(raw)` | 把一条感知 JSON 解析成 `Observation`；字段缺失/类型错误返回 `None` |
| `parse_relative_map(str)` | 解析 9×9 相对位置图，返回 `(dx, dy)`；兼容 `\n` 被转义成字面量 |
| `encode_action(...)` | 生成 `{"tick":..,"session_id":..,"action":..,"direction":..}` |

要点：

- `bool` 是 `int` 的子类，所有整数校验都排除了 `bool`；
- 视野实体的坐标 = 自身绝对坐标 + 相对位移，**不做朝向旋转**；
- 对象与自身同格时图中没有 `2`，按 `(0,0)` 处理；
- 动作方向只允许 `up/down/left/right`，字段一律小写。

### 3.2 `world.py` —— 增量地图 + 代价场

**占据栅格**：`0 未知 / 1 畅通 / 2 障碍`。每帧把视野 9×9 标为畅通，
再把本帧出现的 `obstacle` 实体标为障碍；世界分裂的十字墙按到期 Tick 存进 `temp_block`。

**资源记忆**：`id → (位置, 价值, 最后见到 Tick)`。
若一个已知资源仍在视野内却没再出现，说明被对手采走，计入 `taken_value`（用于修正探索价值的密度估计）。

**敌车记忆**：保存最后位置/血量/是否防御，超过 8 Tick 未再见就丢弃（只用于威胁判断，不用于追猎）。

**代价场 `build_field()`**：四邻接 Dijkstra，一次算出到全图的距离与前驱，供本 Tick 所有候选目标共用。

```
格子代价 = 1.0
         + 0.075            未知格（鼓励走已验证通路，但不禁止探索）
         + 7.0              当前被敌车占据的格
         + 0.95 / 0.22      敌车攻击线（低血 / 高血）
爆炸区、世界分裂十字线 = 不可通行
```

一次 Dijkstra 的成本约 0.2 ms（24×24），500 ms/Tick 下余量极大。

### 3.3 `combat.py` —— 把"打不打"算成分数

规则要点：普通攻击沿方向命中 **1–2 格内最近**的敌车；防御 20→10；出生保护 0；
天下无双 50/10/0 且命中 5×5 全部敌人；洁身自好时打防御目标 = 0 伤害 + 自伤 20。

```python
def attack_options(pos, enemies, purity, unrivaled):
    # 每个方向只取最近的敌人（后面的会被挡住）
    # 收益 = 伤害 × 0.03 + 击杀奖励 1.8 - 反伤 × 0.06
```

`choose_attack()` 再加两道保命闸门：

- 自己处于出生保护 → 不能攻击，直接放弃；
- 自己 HP ≤ 20 且这一下打不死对方 → 不换血，改为脱离。

### 3.4 `events.py` —— 只接收"已经理解的"事件

`ingest(payload, tick, w, h)` 校验 LLM 输出并编译成 `ScheduledEvent`：

| 事件 | 程序如何使用 |
| --- | --- |
| 爆炸 | 生效前 3 Tick 起把矩形设为禁区，自动绕行/撤离 |
| 幻术 | 记录受影响矩形与到期 Tick；再用 `last_action.effective_direction` 自校正 |
| 世界分裂 | 十字线提前 1 Tick 变为不可通行 |
| 天使恩泽 | HP < 70 时作为高价值目标去踩点回血 |
| 天下无双 | 提前去固定堡垒 [11,11]–[13,13]，**每 Tick 在 3×3 内换格移动**累计 10 Tick，拿 5×5 范围攻击 |
| 火爆辣椒 | 点本身可安全站立（交点免疫），不主动绕行 |
| 洁身自好 | 攻击评估自动跳过防御目标；被贴脸时优先防御反击 |
| 潘潘的神 | 移动会获得易伤 → 低血时减少不必要移动、优先防御 |

**校验规则**（防止模型幻觉污染策略）：类型白名单、Tick 边界、矩形裁剪到地图内、
最多 12 条事件、重复 `(类型, 起始Tick)` 去重。校验失败的条目直接丢弃。

### 3.5 `llm.py` —— 异步、单并发、可降级

- 一个后台线程 + 队列，主循环只 `submit()`（非阻塞）和 `drain()`（取结果）；
- 只发 `POST /v1/chat/completions`，`Content-Length` 显式设置，`stream=false`；
- 超时 4.5 s，`rate_limit`/`concurrency_limit` 退避重试，`quota_exceeded` 直接降级停止；
- 统计成功/失败/延迟，**不记录令牌和提示词**；
- 每场至少要有一次成功调用（否则任务分 M=0），因此启动阶段会持续重试"简报"请求（最多 10 次）。

请求体按上游接口逐项写死（网关除 `model` 外原样转发，字段取舍完全由我们控制）：

| 字段 | 值 | 理由 |
| --- | --- | --- |
| `model` | `deepseek-flash` | 主办方统一模型 |
| `thinking` | `{"type": "disabled"}` | 实时决策不需要长思考，省延迟省 token |
| `response_format` | `{"type": "json_object"}` | 逼模型只吐 JSON，解析更稳 |
| `max_tokens` | `512` | 封顶，防止异常长输出拖慢回调 |
| `temperature` | `0.1` | 战术判断要稳定，不要发散 |
| `stream` | `false` | 网关不支持流式 |

**降级链**：上游若返回 400（不认某个可选字段），先去掉 `response_format` 重试，再去掉
`thinking` 重试，最后才判失败——不会因为一个可选参数把整条 AI 链路废掉。
`401/403` 直接停（令牌错），`429 quota_exceeded` 停止请求（额度耗尽）。

自测：`python3 tools/test_llm_payload.py`（起本地替身抓真实请求体，校验字段、降级与开关）。

### 3.6 `collector.py` —— 第一阶段：在线定向采集

每一 Tick 对"已知资源"和"探索前沿"统一打分，取最高者：

```
资源：u = 0.2 × value / (0.32 × d + 0.2)
探索：u = 2.3 × 0.85 × 0.2 × 密度 × 新发现格数 / (d + 3.4)
密度 = min( 剩余价值 / 未知格数 , 1.15 )
```

- `0.2 = 40/200`：1 点资源价值折 0.2 分；
- `0.32d`：折返代价系数。小于 1 表示"只算单程"，更愿意为路边资源绕一小段；
- 探索项用 `新发现格数` 估计"这一步能看见多少新区域"，再乘资源密度换算成期望分数；
- 目标锁定 4 Tick + 1.28 倍切换阈值，避免两个近似候选之间反复横跳。

### 3.7 `strategies/` —— 第二阶段：四种可切换的策略

| 文件 | 策略 | 一句话 |
| --- | --- | --- |
| `greedy.py` | 贪婪型 | 只采集/任务，从不攻击，被贴脸才防御 |
| `aggressive.py` | 侵略型 | 主动接敌，资源只捡 4 格内 |
| `conservative.py` | 保守型 | 拉开距离，边躲边搜，从不攻击 |
| `battle.py` | 综合型 | 资源/任务/对抗统一打分（默认，冲分用） |

四种策略共享 `Brain` 里的 `WorldMap` / `EventMemory` / `LoopGuard`：切换策略只换决策对象，
不清空地图与资源记忆。每个策略都实现了同一接口 `decide(brain)`，内部复用
`resources()` / `reach_target()` / `heal_target()` / `flee_cell()` 等公共工具。

详细行为、阈值、事件响应与实测数据见 [`三种策略说明.md`](三种策略说明.md)。

### 3.8 `battle.py` —— 综合型：任务/资源/对抗统一决策

每 Tick 生成一份候选目标清单（统一折算成"分/步"）：

| 目标 | 效用 |
| --- | --- |
| 到达任务点 | `5 / (0.45d + 0.25)`，一步可达 ×1.8；前 120 Tick ×0.30（先抢资源） |
| 普通资源 | `0.25 × 10 / (0.45d + 0.3)`，任务缺普通时 ×1.40 |
| 高价资源 | `0.25 × 20 / (0.22d + 0.3)`，任务缺高价时 ×2.55 |
| 天使点 | `0.085 × 可回血量 / (d + 2)`，仅 HP < 70 |
| 堡垒 | `10.0 / (d + 2)`，仅在窗口内、且 `剩余时间 > 路程 + 驻留 10 + 2` 时去 |
| 追击 | `(0.03×hp + 1.8) / (0.55d + 击杀所需Tick + 1)`，可斩杀 ×1.35 |
| 探索 | `1.55 × 0.25 × 密度 × 新发现格数 / (d + 3.6)` |

随后叠加**阶段系数**：

```
对抗分已满（D ≥ 500）      × 0.12   （只为同分排名保留一点动机）
收官（剩余 < 180 且 D < 500） × 1.45   （主动找人补伤害）
资源期（R < 120）           × 0.30   （30 分资源 > 15 分对抗，只"顺手打"）
出生保护期                  × 0.25   （打不了，别追）
```

最后叠加 LLM 的 `focus`（最多 ±22%）与 `aggression`（最多 ±12%），保证模型只能"建议"不能"接管"。

### 3.9 `brain.py` —— 决策中枢

一 Tick 的流水线：

```
1. 解析感知（失败 → 忽略）
2. 场次/地图变化 → 清空全部记忆
3. tick 过期 → 丢弃；tick 重复 → 复用缓存动作
4. 融合地图 / 资源 / 敌车
5. drain LLM 结果 → 编译事件
6. 事件文本变化 → 投递新的 LLM 请求（非阻塞）
7. 构建本 Tick 代价场
8. 阶段策略出动作
9. 幻术方向补偿、合法性兜底、缓存
```

阶段识别：`missions` 非空，或地图边长 ≥ 22，或曾经看见过敌车 → 第二阶段；否则第一阶段。
这样不依赖任何本地配置，换场次自动适配。

### 3.10 `node.py` —— 只做搬运

- 订阅 `/team_X/perception`（RELIABLE / VOLATILE / KEEP_LAST(1)）；
- 发布 `/team_X/action`（同 QoS），每 Tick 至多一条；
- 发布 `/team_X/registration`（TRANSIENT_LOCAL 锁存队名，每 3 s 重发一次）；
- 每 2 s 检查 `decision_config.json`，`decision_type` 变化时热切换策略（记忆保留，每场最多 2 次）；
- 决策在回调内同步完成（3–5 ms），LLM 在后台线程；
- 任何异常都只记日志，不退出进程。

## 4. 安全与鲁棒性设计

| 风险 | 处理 |
| --- | --- |
| 感知字段缺失/类型错误 | `parse_perception` 返回 `None`，本帧丢弃，进程继续 |
| 同 Tick 重发 | 返回缓存动作（规则允许重发），不重复推进策略 |
| 上一场动作残留 | `session_id` 变化即清空记忆与缓存 |
| 幻术方向反转 | 用 `last_action.effective_direction` 与实际发送方向比对，自动纠正 |
| 隔墙追不到的敌人 | 路径代价 > 3×直线 + 6 时权重 ×0.15，避免死磕 |
| 两格之间来回横跳 | 9 Tick 内只出现 ≤2 个格子 → 强制改走远点 12 Tick |
| 长时间原地不动 | 4 Tick 未位移 → 清空目标锁；攻击站位不允许选自身格 |
| LLM 超时/额度耗尽 | 主循环照常，事件约束为空，策略退化为"无事件版本" |
| 模型输出非法 JSON | 只做结构校验后丢弃，绝不执行未校验内容 |
| 阵亡 | 只发 `wait`（合法，不增加 invalid_actions） |

### 6.3 日志怎么看

每 25 Tick 一行：

```
t=60 stage=2 pos=(14, 9) hp=80 R=70 D=120 m=1 inv=0 llm=2/2 ev=angel@70-86 | 决策延迟 3.1ms
```

- `R` 资源价值、`D` 有效伤害、`m` 已完成任务数、`inv` 非法动作数；
- `llm=成功/总请求`；`ev` 是已编译事件的摘要；
- 决策延迟持续 > 20 ms 才需要担心（100 ms/Tick 的第一阶段仍有余量）。

## 7. 合规自查（对应规则 §8.1 / §12 / §13）

- 事件文本**只**作为 `llm.py` 的请求内容；代码中没有对事件文本做正则、关键词或模板解析；
- 只用协议列出的 6 个公开话题；
- 不读取 `~/.rmtc-practice/`、网页接口或 `config.json`；
- 不写死令牌、场次 ID、地图、任务坐标、事件日程；
- 决策参数全部属于封存版本；现场只改 `decision_config.json` 的 `decision_type`；
- 不做人工实时操控，程序自主完成感知→决策→动作闭环。

## 8. 常见问题

**Q：为什么不做全局路径规划（A*）而用 Dijkstra？**
地图最大 24×24=576 格，Dijkstra 一次 0.2 ms，且一次就能得到"到所有候选目标"的距离，
比每个目标单独 A* 更快，也让目标效用比较成为可能。

**Q：为什么追猎只看视野内的敌人？**
追记忆位置会被"幽灵目标"拖死（实测出现过 350 Tick 原地振荡）。
敌人离开视野后位置不再可信，追过去大概率扑空，不如继续采集。

**Q：为什么残血不逃，反而有时防御？**
攻击在移动前结算：逃跑这一 Tick 仍然会挨打，而防御能把 20 降到 10。
只有在"这一下能斩杀"或"脱离后确实安全"时才优先移动。

**Q：LLM 挂了怎么办？**
程序不依赖 LLM 也能完整跑完两阶段（移动/攻击/任务都正常），只是不响应随机事件、
任务分按 M=0 计。`llm.py` 会在额度耗尽时自动停止请求，不会刷爆配额。

**Q：换席位/换场次要改什么？**
只改环境变量（`RMTC_TEAM_TOKEN`、`ROS_DOMAIN_ID`、`RMTC_AI_URL`）和启动参数 `team:=B`。
程序从感知读取 `session_id`、`tick`、`map`，不依赖任何本地配置。

## 9. 现场操作清单

1. 开赛前 10 分钟：`source` ROS、设置域与令牌、启动程序；
2. 确认日志出现 `新场次 ...`，且 `t=` 在增长；
3. 确认网页"动作 Tick / 执行 Tick"同时增长，`inv=0`；
4. 第二阶段另开一个终端手工 `curl` 一次网关，确认令牌有效（可选，会消耗一次配额）；
5. 比赛结束后保存日志（`ros2 topic echo` 或程序 stdout），用于复盘与申诉。
